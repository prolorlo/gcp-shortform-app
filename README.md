# 숏폼펫 (ShortFormPet)

숏폼 때문에 공부에 집중하기 어려운 20대를 위한 안드로이드 앱입니다.
유튜브 쇼츠 · 인스타 릴스 · 틱톡 시청 시간을 재고, 덜 볼수록 캐릭터가 자라며, 공부 모드로 줄인 시간을 학업 집중으로 연결합니다.

| 기능 | 내용 |
| --- | --- |
| F1 측정 | 쇼츠/릴스 화면일 때만 1초 단위로 측정 (일반 영상·피드 제외), 틱톡은 앱 전체 |
| F2 단계별 알림 | 목표 전 30분마다, 목표를 넘긴 뒤 15분마다 누적 알림. 20분 넘게 이어 보면 "잠깐 쉬어갈까?" |
| F3 새벽 5시 초기화 | 하루 = 오전 5:00 ~ 다음날 4:59. 5시에 전날 기록으로 캐릭터 정산 |
| F4 캐릭터 "모찌" | 점수 = 100 × 60 / (시청분 + 60). 성장 기준 0 / 10 / 100 / 220 / 400 (베타 5일) |
| F5 기록·설정 | 최근 7일, 하루 목표 30~120분, 이름 변경 |
| F6 공부 모드 | 할 일 3개, 25·50분 세션(쇼츠·릴스·틱톡 차단), 간식, 휴식 쿠폰 |
| F7 연속일수 | 목표 이하인 날 +1, 보호권, 7·30·100일 꾸밈(리본·목도리·별) |
| F8 진입 안내 | 목표를 넘긴 뒤 숏폼을 켜면 3초 안내 화면 ("계속 보기" 항상 있음, 설정에서 끌 수 있음) |

외부 라이브러리 없이 안드로이드 기본 프레임워크만 사용합니다.

## 빌드

1. Android Studio에서 이 폴더를 엽니다. (File → Open → `ShortFormPet`)
2. Gradle 동기화가 끝나면 에뮬레이터나 휴대폰을 고르고 ▶ Run.
   - 명령줄(Windows): `gradlew.bat assembleDebug` → `app\build\outputs\apk\debug\app-debug.apk`
3. 빌드 환경: Gradle 9.5.1, Android Gradle Plugin 9.1.1, compileSdk 37, 기기 Android 8.0(API 26) 이상

## 처음 실행 후

1. 안내 창에서 "동의하고 시작" (수집·전송 항목 안내)
2. "접근성 서비스 켜기" → 설정 → 접근성 → 설치된 앱 → **숏폼펫 시청 시간 측정** 켜기
   - Android 13 이상에서 APK를 직접 설치한 경우 스위치가 회색일 수 있습니다.
     설정 → 애플리케이션 → 숏폼펫 → 오른쪽 위 ⋮ → **제한된 설정 허용** 후 다시 켜 주세요.
3. 알림 허용, 배터리 최적화 제외(권장)

## Firebase 동기화 설정 (아직 주소가 비어 있음)

`Sync.kt`의 `SyncConfig.FIREBASE_DB_URL`이 비어 있으면 전송하지 않고 기기에만 쌓아 둡니다(최대 60일치).

1. Firebase 콘솔에서 프로젝트를 만들고 **Realtime Database**를 생성합니다.
2. 데이터베이스 주소(예: `https://<프로젝트>-default-rtdb.asia-southeast1.firebasedatabase.app`)를 `FIREBASE_DB_URL`에 넣습니다.
3. 규칙(Rules)은 "쓰기만 가능, 읽기 불가"로 둡니다.

```json
{
  "rules": {
    ".read": false,
    "daily": {
      "$anonId": {
        "$date": {
          ".write": true,
          ".validate": "newData.hasChildren(['anonId', 'date', 'watchSec'])"
        }
      }
    }
  }
}
```

전송은 새벽 5시 정산 직후 `PUT <주소>/daily/<익명 ID>/<날짜>.json` 한 건이며, 실패하면 네트워크가 연결될 때 밀린 날짜부터 다시 보냅니다.
보내는 항목은 `SyncManager.kt`의 `buildPayload`에 모여 있습니다. 화면 내용·영상 제목·계정·캐릭터 이름·할 일 내용은 보내지 않습니다.

## 개발자 테스트 메뉴 (디버그 빌드 전용)

Android Studio의 Run이나 `assembleDebug`로 설치하면 설정 탭 맨 아래에 "개발자 테스트" 카드가 보입니다. 릴리스 빌드에는 나오지 않습니다.

| 버튼 | 하는 일 |
| --- | --- |
| 쇼츠/릴스/틱톡 +10분 | 오늘 기록에 가짜 시청 10분 추가. 누적 알림 기준(30분, 목표 이후 15분)을 넘으면 알림도 옴 |
| 시간 +25분 | 앱이 보는 시각을 25분 앞으로. 진행 중인 세션 완료, 쿠폰 소진 확인 |
| 하루 넘기기 | 다음 날 오전 5:01로 넘기고 바로 정산. 결과는 말풍선·"최근 정산"·알림에 표시 |
| 측정 안 된 날로 하루 넘기기 | 오늘을 측정 기록 없는 날로 두고 넘김. 정산·연속일수가 보류되는지 확인 |
| 전체 초기화 | 시청·캐릭터·공부 기록을 지우고 실제 시각으로 복귀 (목표·동의 설정은 유지) |

카드 위쪽 정보 칸에는 앱이 보는 시각, 기록 날짜, 지금 정산하면 받을 경험치, 감지 원본(앞 화면 패키지와 숏폼 판별 결과)이 1초마다 갱신됩니다.
가상 시각을 쓰는 동안에는 서버 전송을 하지 않습니다. 구현은 `DevTools.kt`에 있습니다.

## 데이터 저장

모든 상태는 기기 내부 SharedPreferences 4개 파일에 저장되어 앱을 껐다 켜거나 재부팅해도 유지됩니다.

| 파일 | 내용 |
| --- | --- |
| `usage` | 날짜·앱별 시청 시간, 쿠폰 시청 시간, 측정 시간, 알림 기준, 횟수 기록 |
| `settings` | 하루 목표, 세션 길이, 안내 화면 설정, 동의, 익명 ID, 동기화 대기 목록 |
| `pet` | 이름, 경험치, 체력, 연속일수, 꾸밈, 마지막 정산일, 날짜별 정산 상태 |
| `study` | 할 일, 진행 중인 세션(시작·종료 시각), 켜 둔 쿠폰, 보호권, 날짜별 공부 기록 |

진행 중인 세션과 쿠폰은 "시각"으로 저장하므로, 앱이 꺼져 있던 사이에 끝났어도 다음에 켜질 때 정상 처리됩니다.

## 감지가 안 될 때

유튜브·인스타그램은 업데이트로 화면 내부 ID가 바뀔 수 있습니다.
오늘 탭 "오늘 본 숏폼" 카드의 감지 상태가 쇼츠를 보는데도 "숏폼 화면 아님"이면
Android Studio의 Layout Inspector(또는 `adb shell uiautomator dump`)로 쇼츠 플레이어의 resource-id를 확인해
`ShortFormDetector.kt`의 `YOUTUBE_SHORTS_IDS` / `INSTAGRAM_REELS_IDS`에 추가하세요.
